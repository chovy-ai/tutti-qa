## 5. 关键断言与本轮定稿口径

| 口径 | 结论 | 依据 |
|---|---|---|
| 游客能否读群聊 | 默认可读；「发表评论和群聊聊天」开关同时控制群聊发言和会话评论，关闭后仍可读 | QA 确认，按 #3425 |
| 覆盖哪些身份 | 登录游客为主干，匿名访问只写差异 | QA 确认 |
| 未登录打开游客链接 | 先匿名只读进入 → 点受限操作时跳登录 → 回到房间后弹加入框 → 成为游客；登录前点的操作不会自动执行 | QA 确认，#3282 与路由测试 |
| 更换游客链接 | 旧链接失效，已加入的游客保留 | QA 确认 |
| 游客房间是否进入游客自己的房间列表 | 进入，并带「游客」标识；被移出后消失 | QA 确认 |
| 共享 Agent 消息里的图片和附件 | 写成正确行为（能看到）；因 #3488 已回滚，当前预计失败，按缺陷跟踪 | QA 确认 |
| 实验开关「游客模式」 | 不单独出用例，默认已开启 | QA 确认 |
| 「游客访问」tab 的可见条件 | 仅房主可见、实验开关已开、不是公开房间 | 代码 `RoomSharePanel.tsx` |
| 暂停链接 / 关闭模式 | 暂停只停止新加入；关闭后所有游客失去访问，历史保留，重新开启不恢复原游客 | 中文文案 |

容易漏或写反的断言：
- **反向断言**：关闭讨论开关后游客仍可读群聊；暂停期间已有游客仍可访问；重新开启游客模式后原游客不会自动恢复。这三条都在用例备注里写明了"不是缺陷"。
- **口径相反的成对设计**：
  - 「暂停链接」只停止新加入，已有游客保留；「关闭游客模式」会让所有游客失去访问。
  - 「更换链接」让旧链接失效，但已有游客保留。
- **身份对照**：匿名访问组最后一条把两种身份的能力逐项对照，任何一项只在某一种身份上缺失或多出、又不在已知差异内，都视为缺陷。
- **越权**：游客不能操作 Agent、不能编辑成果、不能读取未授权内容。每类都包含用快捷键、篡改前端状态、直接调用接口来绕过的检查。
